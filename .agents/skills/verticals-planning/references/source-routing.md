# Source routing

Use the least access needed to prove why a goal exists, what completion means, and what remains unknown.

## Authority order

1. **Direct commitments:** user statements, explicit agreements, promises, and exact source passages. These can prove task existence and ownership.
2. **State artifacts:** documents, repositories, delivered files, sent messages, payments, calendar events, and board records. These prove current state.
3. **Strategic context:** values, strategy, retrospectives, and accepted plans. These explain rationale and parentage but do not create tasks.
4. **Discovery indexes:** summaries, search results, extracted action items, handoffs, and prior agent reports. These identify where to look; verify the underlying source.
5. **Feasibility evidence:** calendar, measured workload, payments, and comparable completed work. These support dates and metrics only.

The newest direct correction wins when sources conflict. Record the conflict; do not blend versions.

## Lookup sequence

1. Read the goal and its current board context.
2. Resolve the entity: project, person, organization, aliases, and nearby goals.
3. Inspect any existing evidence status and receipt.
4. Use lightweight indexes to locate candidate sources.
5. Read the primary source at the scope required for the claim.
6. Cross-check the actual artifact when the claim concerns delivery, acceptance, payment, schedule, or implementation.
7. Build a claim-to-source map and stop when all required claims are supported.

## Optional connected inputs

Messaging systems, email, calendars, meeting transcripts, repositories, payment data, and time-tracking systems may be useful additional inputs when configured and authorized. They are optional connectors, not hard-coded dependencies.

- Refresh the relevant conversation before relying on it.
- Distinguish people and projects with the same or similar names.
- A message summary is not proof of an agreement; read the underlying exchange.
- A meeting proves intent, not implementation.
- A repository and verified tests prove implementation state better than a discussion.
- A calendar shows fixed commitments, not automatic capacity.
- Message counts and elapsed chat spans are not focused effort.

## Provenance gate

For each factual sentence proposed for a card:

1. Write the claim neutrally.
2. Point to a primary source.
3. Confirm the source supports the exact entity, tense, owner, and state.

If any step fails, remove the sentence, keep it as a hypothesis outside the board, or ask for the missing choice.
